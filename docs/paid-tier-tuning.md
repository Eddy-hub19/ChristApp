# Платный Render (0.5 CPU / 512 МБ): настройка и замеры

Ветка `perf/paid-tier-tuning`. Все числа получены `backend/scripts/load-scenarios.ts` на локальной БД (Apple M2), окно 40 с.
Это **модель**, а не замеры самого Render: реальный коэффициент «ядро Render / M2» даёт кнопка «Замерить скорость CPU» в админке.

## 1. Лимиты «Отары»
6 игроков, до 8 ботов (8 → 3 по мере прихода людей), 10 Гц, автоснижение частоты — страховка. Таблица значений для free / 0.5 / 1 vCPU — в `flock.config.ts`.
Админка «Процессы»: бюджет CPU из `RENDER_CPU_BUDGET_MS` (по умолчанию 500), «светофор» CPU считается от бюджета.

## 2. Запросы к БД (запросов/с, 2 игрока, 40 с)

| Сценарий | До | После | Что было причиной |
|---|---|---|---|
| Простой (2 сокета + HTTP-опросы клиентов) | 0.2 | 0.2 | только опросы `/push/*`, `/watch-rooms` |
| «Отара» ×2 | 0.4 | 0.2 | heartbeat `presence:activity` каждые 15 с = 2 запроса |
| «Отара» ×6 | 1.2 | 0.6 | то же |
| Snake-дуэль | 0.4 | 0.2 | то же |
| **Snake классика** | **90.9** | **0.2** | `snake-state` ~14/с × 3 запроса (доступ + title комнаты) |
| Открытый чат (сообщения, набор, прочитано) | 10.9 | 5.8 | остаток — реальные записи: сообщения, `RoomReadState` |
| Кинотеатр | 0.1 | 0.1 | |

Стоимость одного события (запросов): `roomViewState` 2→0, `roomTyping` 2→0, `gameSync` 2→0, `snake-state` 3.1→0, `snake-score` 3→0,
`presence:activity` (heartbeat) 1.7→0.3, `markRoomRead` 3.1→1 (остаётся сам upsert), HTTP `/push/status` 2→1, `/push/unread-summary` 4→3.1.
Проверка подозрений: JWT по сокету уже читался один раз на соединение; `presence:state` heartbeat, ввод «Отары», события кинотеатра — 0 запросов;
`lastSeenAt` писался только при уходе в офлайн (теперь ещё и с тротлингом 15 с).
**Вывод:** сама «Отара» БД почти не нагружает (≈1 запрос/с вшестером). Очередь пула 10/10 при ~1.5 с отклика БД объясняется
не её запросами, а медленной БД (RTT ~94 мс: 90 q/с классической змейки × 94 мс = ~8.5 занятых соединений) и нехваткой CPU на free-тарифе.

## 3. RTT БД
Neon: `us-east-1`, хост **без** `-pooler`. Регион Render из кода не определить (нет в env) — смотреть в Dashboard → Settings → Region; задать `RENDER_REGION`.
Админка показывает регион БД, регион сервера, RTT (50 × `SELECT 1`, медиана/p95). План переноса: `docs/region-migration.md`.

## 4. Общий прогон: «Отара» ×6 + чат с перепиской + кинотеатр одновременно
Квота CPU эмулируется `cfs-throttle` (CFS: N мс на 100 мс), БД через прокси с RTT 94 мс (как сейчас). 3 прогона на конфигурацию в худшем режиме, цифры — диапазон.
«q50» = 0.5 vCPU при ядре, равном M2; «q12.5» = 0.5 vCPU при ядре в 4 раза медленнее M2 (худший случай из `docs/flock-perf.md`).

| Метрика | До (main) | После |
|---|---|---|
| CPU процесса, % ядра (среднее / макс. зразок), q50 | 6.1 / 9.9–10.3 | 5.5–6.6 / 9.6–10.9 |
| CPU, q12.5 | 5.2–5.3 / 6.2–6.6 | 3.8–5.0 / 5.1–7.4 |
| Лаг event loop p99 (макс. за прогон), q50 | 2.5–4.3 мс | 3.9–6.7 мс |
| Лаг event loop p99, q12.5 | 3.2–3.4 мс | 3.3–4.1 мс (один выброс 88 мс в первом прогоне из трёх) |
| Запросов к БД/с (смесь) | 11.4–13.6 | 6.5–6.6 |
| Snake классика при RTT 94 мс: запросов/с / очередь пула (макс.) | 91.5 / **24** | 0.2 / **0** |
| Очередь пула, смесь, RTT 94 мс | 0–8 (всплески при подключении) | 0–7 (всплески при подключении) |
| Очередь пула, смесь, RTT 3 мс (после переноса в один регион) | — | 0 |
| RTT до БД | 94 мс (со слов; в админке теперь измеряется) | 94 → ожидается 1–5 мс после `region-migration.md` |

Цель p99 < 50 мс выполняется (кроме одного выброса при жёсткой квоте). «После» несёт больше ботов (минимум 3 вместо 2 при 6 людях), поэтому CPU арены сопоставим.
Очередь пула в смеси — только короткие всплески при одновременном подключении всех сокетов (десятки запросов сразу при RTT 94 мс); в установившемся режиме очереди нет.
Чаты не тормозят: лаг loop единицы мс.

## Воспроизведение
```bash
npm run build
LOAD_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/db?schema=public \
LOAD_QUOTA_MS=50 LOAD_DB_RTT_MS=94 \
  node -r ts-node/register/transpile-only -r tsconfig-paths/register scripts/load-scenarios.ts mixed 40
```
`probe` — стоимость одного события; `LOAD_BACKEND_DIR` — сборка «до». Квота: `clang -O2 -o scripts/cfs-throttle scripts/cfs-throttle.c` (macOS).
Скрипт отказывается работать с любой БД, кроме localhost.
